# Определение терминов

* **HTTP (HyperText Transfer Protocol):** Протокол передачи гипертекста. Это базовый протокол прикладного уровня, используемый для передачи данных (веб-страниц, изображений, API-ответов и т.д.) между клиентом и сервером.
* **HTTPS:** Защищенная версия протокола HTTP. Главное отличие заключается в использовании криптографических протоколов (SSL/TLS) для шифрования передаваемых данных, что защищает их от перехвата третьими лицами.
* **Клиент-серверная модель:** Архитектура сетевого взаимодействия, при которой "клиент" (например, браузер) отправляет запрос на получение услуги или данных, а "сервер" обрабатывает этот запрос и возвращает ответ.
* **Идемпотентность:** Свойство методов, при котором многократное одинаковое выполнение одного и того же запроса дает точно такой же результат и состояние на сервере, что и однократное выполнение (например, методы GET, PUT, DELETE идемпотентны, а POST — нет).

## 2.1. Разбери запрос

**Ответы по HTTP-запросу:**
1. Какой метод используется: Метод POST.
2. Какой путь (endpoint) запрашивается: Путь /api/users.
3. Какая версия HTTP: Версия HTTP/1.1.
4. Что означает заголовок Content-Type: Он сообщает серверу формат данных, переданных в теле запроса. Значение application/json означает, что данные представлены в формате JSON.
5. Что означает заголовок Authorization: Этот заголовок передает данные для проверки прав доступа. Значение Bearer указывает на использование токена авторизации.
6. Где находится тело запроса: Тело запроса находится в самом низу, после пустой строки, отделяющей его от заголовков (строка с именем и email).

**Ответы по HTTP-ответу:**
1. Что означает статус-код 201: Статус 201 Created означает, что запрос выполнен успешно, и в результате на сервере был создан новый ресурс.
2. Зачем нужен заголовок Location: Он указывает адрес (путь) вновь созданного ресурса, по которому к нему можно обратиться (/api/users/42).
3. Что находится в теле ответа: В теле ответа находятся данные только что созданного пользователя, которому база данных сервера уже присвоила уникальный идентификатор (id: 42).

## 2.3. Собери запрос сам

Ниже представлены структуры запросов в текстовом виде (в качестве базового пути используем /products):

1. **Получение списка всех товаров:**
Используется метод GET. Запрашиваемый путь: /products. Тело запроса оставляем пустым.

2. **Создание нового товара с именем "Ноутбук" и ценой 50000:**
Используется метод POST. Запрашиваемый путь: /products. В заголовках передаем Content-Type: application/json. В теле запроса отправляем данные: {"name": "Ноутбук", "price": 50000}.

3. **Удаление товара с id=7:**
Используется метод DELETE. Запрашиваемый путь должен указывать на конкретный товар: /products/7. Тело запроса не требуется.

4. **Обновление товара с id=3 (изменить цену на 45000):**
Используется метод PATCH (подходит для частичного обновления) или PUT. Запрашиваемый путь: /products/3. В заголовках указываем Content-Type: application/json. В теле запроса передаем только обновленные данные: {"price": 45000}.
